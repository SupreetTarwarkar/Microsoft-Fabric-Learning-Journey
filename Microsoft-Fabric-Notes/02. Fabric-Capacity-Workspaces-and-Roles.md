# Chapter 2: Fabric Capacity, Workspaces & Roles

---

## 2.1 Fabric Capacity

Microsoft Fabric uses **Capacity** to provide the compute resources required to run Fabric workloads.

Whenever we perform operations such as:

- Running a Data Pipeline
- Executing a Notebook
- Performing Spark transformations
- Running Dataflow Gen2
- Querying a Warehouse
- Refreshing a semantic model
- Using Power BI workloads

these operations require computational resources.

A simple way to remember:

> **Capacity = Compute power available to Microsoft Fabric workloads.**

This is different from OneLake, which is primarily the common storage foundation.

### Simple Understanding

| Fabric Component | Main Purpose |
|---|---|
| **OneLake** | Storage |
| **Fabric Capacity** | Compute |
| **Workspace** | Organizes Fabric items |
| **Fabric Workloads** | Perform the actual tasks |

---

## 2.2 Capacity Units (CU)

Fabric capacity resources are measured using **Capacity Units (CUs)**.

Capacity Units represent the amount of compute resources available to the Fabric capacity.

For example:

| Fabric SKU | Capacity Units |
|---|---:|
| F2 | 2 CU |
| F4 | 4 CU |
| F8 | 8 CU |
| F16 | 16 CU |
| F32 | 32 CU |
| F64 | 64 CU |

The number generally represents the number of **Capacity Units** associated with that SKU.

A simple relationship is:

> **Higher F-SKU → More Capacity Units → More compute resources available**

Microsoft Fabric capacities are available through different **F-SKUs**.

Examples include:

As the capacity size increases, more compute resources become available to support Fabric workloads.

F8

F16

F32

- Planned

- Optimized

## 2.4 Shared Capacity Across Workloads

An important concept is that Fabric capacity is not only for Power BI.

The same capacity can support different Microsoft Fabric workloads.

For example:

```text
Fabric Capacity
      │
      ├── Data Pipeline
      ├── Notebook
      ├── Dataflow Gen2
      ├── Warehouse
      ├── Semantic Model
      └── Power BI
```

All these activities can consume capacity resources.

### Practical Example

Suppose multiple heavy processes run simultaneously:

- Large Notebook transformation
- Pipeline ingestion
- Dataflow Gen2 refresh
- Warehouse query
- Power BI refresh

These workloads may compete for the available capacity resources.

Therefore:

> **Capacity planning and monitoring become important when multiple Fabric workloads operate at the same time.**

---

## 2.5 Why Capacity Matters

Capacity affects the resources available to execute Fabric workloads.

If the environment has insufficient capacity for the amount of work being performed, we may experience:

- Slower execution
- Longer refresh duration
- Delayed workloads
- Throttling
- Poor query performance

Capacity should therefore be monitored rather than assuming every Fabric workload has unlimited compute.

### Real-World Example

Consider a workspace called:

**Retail Analytics**

It contains:

- `lh_retail`
- `pl_sales_ingestion`
- `nb_bronze_to_silver`
- `wh_retail`
- `Retail Semantic Model`
- `Retail Sales Report`

A normal daily workflow might look like:

```text
8:00 AM
Pipeline loads new sales data
        ↓
8:10 AM
Notebook transforms Bronze → Silver
        ↓
8:20 AM
Gold tables are prepared
        ↓
8:30 AM
Warehouse queries execute
        ↓
9:00 AM
Users access Power BI reports
```

All these operations can place demand on Fabric capacity.

Therefore:

> **Capacity is not simply a licensing concept. It represents the compute resources available to run the analytics solution.**

## 2.6 Fabric Trial Capacity

For learning and evaluation, Microsoft provides Fabric trial capabilities subject to Microsoft's current eligibility and trial policies.

The learning environment used a trial capacity so that Fabric features could be practiced without initially purchasing a production Fabric capacity.

### Important Learning

> **A trial environment is useful for learning, but it should not be confused with how an organization plans and manages production capacity.**

Production environments require proper:

- Capacity planning
- Monitoring
- Cost management
- Security
- Governance

## 2.7 F64 and Power BI

One important capacity point is **F64**.

F64 is significant because Fabric capacities at **F64 or higher** provide Power BI consumption capabilities comparable to Premium capacity for viewers.

In practical terms, with an appropriate F64+ Fabric capacity, users with a free Power BI license can consume Power BI content when that content is hosted in the qualifying capacity, subject to the applicable Power BI licensing rules.

### Important

This does **not** mean:

> **F64 makes everything free.**

Licensing, publishing, sharing and capacity requirements still need to be considered separately.

The important learning is:

> **F64 is an important Fabric capacity threshold, especially when Power BI report consumption and organizational distribution are involved.**

## 2.8 Fabric Workspace

A **workspace is a collaborative environment where Fabric items belonging to a solution or project are created and managed.**

For example:

### Workspace: Sales Analytics

It could contain:

- Sales Lakehouse
- Sales Pipeline
- Sales Notebook
- Sales Warehouse
- Sales Semantic Model
- Sales Power BI Report

Therefore:

> **Workspace = Logical container and collaboration area for Fabric project items.**

### Why Do We Need Workspaces?

Without proper workspace organization, Fabric items across different projects would become difficult to manage.

Workspaces help with:

- Project organization
- Collaboration
- Access control
- Item management
- Security
- Governance
- Deployment
- Capacity assignment

### Example of Better Organization

Instead of keeping unrelated items together:

```text
HR_Report
Sales_Pipeline
Finance_Lakehouse
HR_Notebook
Sales_Report
```

we can organize them logically.

**HR Analytics Workspace**

- HR Lakehouse
- HR Pipeline
- HR Report

**Sales Analytics Workspace**

- Sales Lakehouse
- Sales Pipeline
- Sales Report

**Finance Analytics Workspace**

- Finance Warehouse
- Finance Semantic Model
- Finance Report

This makes the Fabric environment easier to manage.

### Capacity and Workspace Relationship

A useful relationship is:

```text
Fabric Capacity
      ↓
Workspace
      ↓
Fabric Items
```

For example:

```text
F64 Capacity
      ↓
Sales Analytics Workspace
      ↓
Lakehouse
Pipeline
Notebook
Warehouse
Semantic Model
Power BI Report
```

The workspace can be assigned to a Fabric capacity, and the items inside that workspace use available capacity resources when workloads execute.

### Easy Way to Remember

> **Capacity provides resources. Workspace organizes items. Items perform the work.**

## 2.9 Workspace Roles

Not every person working with a Fabric workspace should have the same permissions.

Fabric provides four main workspace roles:

1. **Admin**
2. **Member**
3. **Contributor**
4. **Viewer**

These roles provide different levels of access.

### Admin

**Admin** has the highest level of control over a workspace.

Typical responsibilities can include:

- Managing workspace access
- Managing workspace settings
- Adding or removing users
- Managing Fabric items
- Controlling workspace-level configuration

> **Admin = Workspace administrator**

Admin access should normally be limited to people who genuinely need administrative control.

### Member

A **Member** can actively collaborate within the workspace and has significant permissions for working with its content.

Members are generally involved in creating and managing Fabric solutions but do not represent the same administrative level as Admin.

> **Member = Strong collaboration and content-management access**

### Contributor

A **Contributor** is mainly intended for users who need to create and modify content within the workspace.

For example, developers working on:

- Pipelines
- Notebooks
- Reports
- Lakehouses
- Other Fabric items

may need Contributor-level capabilities depending on the organization's security design.

> **Contributor = Can create and modify content without being the workspace administrator**

### Viewer

A **Viewer** primarily consumes content rather than developing or managing it.

For example, a business user may only need to open and view a report.

They do not necessarily need permission to:

- Edit the report
- Modify a pipeline
- Change a Notebook
- Delete Fabric items
- Manage workspace users

> **Viewer = Primarily read and consume access**

### Workspace Roles — Simple Comparison

| Role | Simple Understanding | Typical User |
|---|---|---|
| **Admin** | Highest workspace control | Workspace / Platform administrator |
| **Member** | Strong collaboration and management capabilities | Senior project / team member |
| **Contributor** | Creates and modifies workspace content | Developer / Analyst / Engineer |
| **Viewer** | Primarily consumes content | Business / Report consumer |

---

## 2.10 Principle of Least Privilege

A very important real-world security principle is:

> **Give users only the minimum level of access required to perform their job.**

This is called the **Principle of Least Privilege**.

### Example

If a manager only needs to view a Power BI report, giving them Admin access to the complete Fabric workspace would normally be unnecessary.

Instead:

```text
Requirement
View Report
     ↓
Provide appropriate viewing / consumption access
```

rather than:

```text
View Report
     ↓
Give Admin access to everything
```

This becomes extremely important when working with real organizational data.

---

## 2.11 Workspace Access vs Data Access

Another important distinction is:

> **Access to a workspace and access to specific data are related, but they are not exactly the same thing.**

A user may have access to an analytics solution while additional security controls determine what data that user is allowed to see.

### Example

Two regional managers may open the same Power BI report.

However:

```text
North Manager → North Region

South Manager → South Region
```

This can be controlled through mechanisms such as **Row-Level Security (RLS)**.

Therefore, security can exist at multiple levels.

### Important Difference

| Concept | Main Purpose |
|---|---|
| **Workspace Access** | Controls access to the workspace and its items |
| **Workspace Role** | Controls what a user can do in the workspace |
| **Data Security** | Controls which data the user is allowed to see |

More detailed data security concepts are covered later under **Security & Governance**.

## 2.12 Capacity Monitoring

In production, we should understand how Fabric capacity resources are being consumed.

Examples of questions we may need to answer:

- Which workload is consuming significant capacity?
- Why did a process suddenly become slower?
- Are multiple workloads running simultaneously?
- Is the current capacity sufficient?
- Are workloads being throttled?
- Do we need optimization before increasing capacity?

A useful production mindset is:

> **Do not immediately solve every performance problem by purchasing more capacity. First understand what is consuming the capacity and whether the workload can be optimized.**

### Practical Architecture to Remember

```text
Microsoft Fabric
      ↓
Fabric Capacity
      ↓
Workspace
      ↓
Fabric Items
      ↓
OneLake
```

Where:

**Fabric Capacity**

Provides compute resources.

**Workspace**

Organizes the solution and controls collaboration.

**Fabric Items**

Examples:

- Pipeline
- Dataflow Gen2
- Notebook
- Lakehouse
- Warehouse
- Semantic Model
- Power BI Report

**OneLake**

Provides the common data storage foundation.

### Important Differences

| Concept | Main Purpose |
|---|---|
| **OneLake** | Storage foundation |
| **Capacity** | Compute resources |
| **Workspace** | Organization and collaboration |
| **Workspace Role** | Controls what a user can do within the workspace |
| **Fabric Item** | Actual object used to perform a task |
| **Workload** | Fabric capability used for a type of analytics work |

Do not confuse these concepts.

## 2.13 Interview Understanding

### What is Fabric Capacity?

Fabric Capacity is the pool of compute resources used to execute Microsoft Fabric workloads.

Capacity is represented using **Capacity Units (CUs)**, and Fabric F-SKUs provide different levels of available compute resources.

### What is the difference between OneLake and Fabric Capacity?

> **OneLake provides the common storage foundation, while Fabric Capacity provides the compute resources required to execute workloads.**

### What is a Fabric Workspace?

A Fabric Workspace is a collaborative environment used to organize and manage Fabric items such as:

- Lakehouses
- Warehouses
- Pipelines
- Notebooks
- Semantic Models
- Power BI Reports

### What are the main workspace roles?

The four main workspace roles are:

> **Admin → Member → Contributor → Viewer**

They provide different levels of permissions depending on what the user needs to do.

### Why shouldn't everyone receive Admin access?

Because production systems should follow the **Principle of Least Privilege**.

Users should receive only the permissions necessary for their responsibilities.

This reduces security risk and prevents unnecessary changes to production resources.

### Why does capacity monitoring matter?

Pipelines, Notebooks, Warehouses, Semantic Models and Power BI workloads can consume capacity resources.

Monitoring helps identify:

- Performance problems
- High resource consumption
- Workload contention
- Throttling
- Optimization opportunities

## 2.14 Key Takeaways

1. **Fabric Capacity provides the compute resources required to run Fabric workloads.**

2. Capacity resources are measured using **Capacity Units (CUs)**.

3. Fabric capacities use **F-SKUs**, such as:
   - F2
   - F4
   - F8
   - F16
   - F32
   - F64

4. **Higher F-SKU generally means more available capacity resources.**

5. Multiple Fabric workloads can consume resources from the same capacity.

6. **OneLake and Capacity are different:**

   > **OneLake = Storage**  
   > **Capacity = Compute**

7. A **Workspace** is a collaborative container used to organize Fabric project items.

8. Fabric workspace roles are:

   > **Admin → Member → Contributor → Viewer**

9. Users should be given permissions according to the **Principle of Least Privilege**.

10. **Workspace access does not automatically mean unrestricted access to every piece of data.** Additional data-security mechanisms can be applied.

11. **F64 is an important capacity level**, particularly in relation to Power BI consumption and Fabric licensing scenarios.

12. In production, capacity should be **monitored and optimized**, not treated as unlimited compute.

13. The relationship to remember is:

> **Capacity provides compute → Workspace organizes the solution → Fabric items perform the work → OneLake provides the common storage foundation.**
